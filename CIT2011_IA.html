1. Overview & Scenario

In this lab, you will act as a front-end developer building a responsive, multi-page client-side registration system for a fictitious tech conference called "Coding Conf". The workflow moves a user from discovering event details to filling out a form, which dynamically outputs a stylized, customized digital ticket.

Responsive Design:

  • Users may be on phones, tablets, laptops, desktops or large displays. Design content first; avoid assuming a single fixed screen width.
  • Use flexible layouts with Flexbox/Grid, relative units and responsive media.
  • Use Position, and Float properties.
  • Include fluid typography
  • CSS custom properties
  • Test at multiple viewport sizes using DevTools'responsive mode. Include screenshots of test results
  • Can a user read, tap, navigate and complete the task comfortably?

Accessibility:

  • Accessible sites are designed so people with disabilities can interact meaningfully with the interface.
  • Use semantic HTML before reaching for ARIA: headings, nav, main, buttons, labels and lists communicate structure.
  • Ensure keyboard access, visible focus, readable contrast, useful alternative text and understandable forms.
  • Accessibility is not a “final check”; it should influence HTML, CSS, JavaScript and design decisions from the start.

Modern Selector Tools:

  • For example, :is(), :where(), :not() and :has() can reduce repetitive selectors.

You must implement this project using ONLY the features and data provided in the Week 1 - Week 6 material from the CIT2011 module. Strictly using semantic HTML5, custom CSS3 layouts (Flexbox/Grid), and Vanilla JavaScript for form parsing, form checking, client-side persistence, and rendering logic.

2. System Architecture & Workflow Requirements

Your web application directory must encompass three independent view states or pages:

  1. Landing Page (index.html): A promotional launch page containing event headers, schedule metadata (Date: October 26, 2026; Location: Papine, Kgn), structural descriptions, and an actionable "Register Now" link or button leading to the form page.
  2. Registration / Login Page (login.html): Contains the secure client form gathering user fields. It must process user inputs and handle client-side validations locally before advancing.
  3. Ticket Confirmation Page (ticket.html): The final visual state displaying a dynamic dashboard containing a success confirmation text element alongside an advanced, glassmorphism-themed conference ticket populated by user parameters.

Deductions (Up to 5 marks per violation) for poor code formatting, chaotic indentations, missing documentation comments, unreferenced dead code loops, or copy-paste architecture omissions, broken links, missing accessibility features, etc.

3. Technical & Engineering Specifications

A. Structural & Layout Integrity (HTML5 & CSS3)

  • Semantic Architecture: Build pages using clear layout components (<header>, <nav>, <main>, <section>, <footer>).
  • Aesthetic Themes & Effects: Mimic a futuristic style leveraging dark purple space backgrounds, vibrant typography gradients, and custom modern visual rules. Do not link utility style packages or web frameworks (e.g., Tailwind CSS, Bootstrap).
  • Ticket Visual Matching: The template on ticket.html must accurately lay out:
    • The master banner confirming standard textual messages ("Congrats, [Name]! Your ticket is ready.").
    • A premium ticket badge implementing glassmorphism characteristics (semi-transparent blurred backdrops, fine white bounds).
    • Strategic arrangements showing full details: the matching "Coding Conf" branded title icon, specific metadata strings, a serial string tracker (e.g., #01609), the custom image profile picture, the parsed name string, and an accompanying GitHub profile link.

B. Dynamic Logic & Form Engineering (JavaScript)

  • State Persistence: Transfer verified properties across execution windows seamlessly via standard browser interfaces like localStorage or sessionStorage.
  • Form Checking Controls: Intercept form submissions inside login.html using event handlers. Programmatic rules must execute clean, contextual error labels to the DOM if criteria fail:
    • Full Name: Required field, cannot consist of empty spaces.
    • Email ID: Enforce strict structure checks matching explicit string regular expressions (user@domain.com).
    • GitHub User Tag: Enforce a standard user handle requirement beginning with the explicit @ prefix.
    • Avatar Graphic Upload: Validate presence and enforce system constraints validating explicit image types (JPEG/PNG) and size constraints (e.g., beneath 500KB).
  • Dynamic DOM Mutation: During execution of ticket.html, query stored properties locally to populate your target elements dynamically. Implement boundary code blocks: if direct route manipulation is attempted without state data present, immediately trigger client routing redirections forwarding the visitor back to index.html.

4. Suggested Implementation Roadmap

  • Architecture & Stylesheets: Focus on component design. Wireframe and assemble structural markup templates across all views. Craft theme rules, asset containers, grid structures, responsive breakpoints, and glass design features.
  • Business Logic & Form Validation: Focus on dynamic behaviors. Code form handlers, pattern filters, and validation rules. Setup persistence keys and read states securely during initialization of the ticket dashboard. Debug file parsers and complete rigorous execution tests.
